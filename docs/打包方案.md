# M5 Note boot.img 打包方案（2026-11-26）

## 结论
打包脚本已写好（`mainline/7.3.1/mkimage-m5note.sh` + `check-dtb-m5note.py`），
**物料齐了就能跑**。当前缺 3 样物料，都不难补，且全部可在不写设备的前提下拿到。

## 打包链路（4 步）
1. 构建 initramfs：busybox + init.sh + tablet-init.sh → `initramfs.cpio.gz`
2. DTB 校验：跳过 ov0.dtbo overlay（设备无 odmdtbo 分区），保留 __symbols__ + reserved-memory 检查
3. `Image.gz` + DTB 拼接 → 复用 stock boot.img 头打包（保留 MTK 私有扩展字段 1644/1648/1652）
4. 回读校验打进去的 DTB 就是检查过的那个

## 物料清单（3 样缺）

### 1. `dl/busybox/x/usr/bin/busybox`（静态 aarch64 busybox）
k50v1 README：需 busybox **1.37.0**，静态编译：
```sh
wget https://busybox.net/downloads/busybox-1.37.0.tar.bz2
tar xf busybox-1.37.0.tar.bz2 && cd busybox-1.37.0
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- defconfig
# 打开 CONFIG_STATIC=y（make menuconfig 或 echo 到 .config 后 olddefconfig）
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc)
mkdir -p /path/to/repo/mainline/7.3.1/dl/busybox/x/usr/bin
cp busybox /path/to/repo/mainline/7.3.1/dl/busybox/x/usr/bin/busybox
```
（laptop 上本地 `/usr/bin/busybox` 是 x86，不能用；`/mnt/shared` 里没有现成 arm64 静态版）

### 2. `images/boot-stock.img`（你设备的原厂 boot，只取头）
在 **你同意且设备只读**的前提下，从设备提取（dd 只读，不写设备）：
```sh
ssh root@192.168.31.213 'dd if=/dev/block/mmcblk0p22 bs=1M count=16' > images/boot-stock.img
```
用途：脚本 `hdr = bytearray(d[:2048])` 复制它的头（含 MTK 私有字段），
再替换 kernel/ramdisk 长度和 SHA1。**cmdline 保持原厂**（`bootopt=64S3,32N2,64N2`）。

### 3. CI 产物里的 `Image.gz` 和 `mt6755-m5note.dtb`
从最新成功 run（`45790670725`）下载 artifact，解出：
- `Image.gz-dtb` 里就是 `Image.gz + DTB` 拼好的——脚本需要分开的 `out/arch/arm64/boot/Image.gz` 和 DTB。
  可从 CI 工作目录直接取（若保留），或从我提供的产物拆分：
  DTB 带 FDT magic `d00dfeed`，从 `Image.gz-dtb` 里定位切出后半段即 DTB，前半段即 Image.gz。

## 适配点说明（和 k50v1 原版的差异）
| 项 | k50v1 原版 | M5 Note 版 | 原因 |
|---|---|---|---|
| DTB 文件名 | mt6750-k50v1-tablet.dtb | **mt6755-m5note.dtb** | 我们派生的板级 dts |
| ov0.dtbo overlay 检查 | 必须 | **跳过** | 设备 GPT 无 odmdtbo 分区 |
| cmdline | 带 console/earlycon/maxcpus | **原厂简单 cmdline** | 你选的原厂头；代价：无串口日志 |
| rootfs | `/data/linux/debian` | 照搬（你选的） | 需你后续在 userdata 放 Debian，否则停在 initramfs |

## 关于"照搬 k50v1 rootfs"的现实提醒
k50v1 的 `init.sh` 假设 `/data/linux/debian` 有 Debian rootfs 并 `switch_root` 进去。
你的 M5 Note 没有这个目录 → 会走 initramfs 里的 rescue 路径（USB 网络 + 超时重启）。
首次测试建议：先确认内核能起到 initramfs shell（看 `/dev/kmsg` → ramoops，
或插 USB 看 192.168.77.2），再决定是否放 Debian。

## 体积
- boot.img = 头(2KB) + kernel(8.55MB) + ramdisk(小) → 约 9–11 MB，**远小于 16.8MB** ✅
- 模块（502 个 .ko，19.85MB）放 rootfs（system 2.68GB），不进 boot

## 刷机前必做
1. **备份原 boot**：`ssh root@192.168.31.213 'dd if=/dev/block/mmcblk0p22 of=/sdcard/boot.img.bak'`（写的是 /sdcard，不写分区）
2. 用 SP Flash Tool 时**逐行核对**：16MB 的 boot.img 填到 `boot` 行，别填到 `lk` 行（会溢出覆盖 lk2/boot，只能 BROM 恢复）
3. 首次测试走 `recovery` 选 mainline（原厂头方式，不动默认启动）
