## 1. 项目目标（原始诉求）

把 MediaTek MT6755（Helio P10）老手机的 kernel 反编译/移植到主线内核，**几天内**做出一个能当服务器用的主线内核：
- 网络（WiFi 必需；没屏幕没触摸可以）
- USB、充电、电池/电源管理
- Docker / LXC（容器能力，几乎全开）
- 全部工作必须在用户自己的 repo 里，不建独立目录

用户明确不接受的：几周/几年的周期、"做不了"的托词、乱改、 premature CI、频繁提问。
最终用户选择：先做 headless 服务器内核；屏幕能轻松加就加、不行就算；最终目标 = 刷 boot 分区后直接启动设备上已有的 Debian（不再经安卓 chroot）。

## 3. 方法论（走过的弯路和最终路线）

### 3.1 路线选择
1. **最初**：想用 6.12 内核 + 自己改 API（cfg80211 签名、cookie、rx_addr 等反复出错）→ **放弃**。教训：不要手工 backport 不匹配的驱动 API。
2. **换成 Linux 7.3.1 + pminervini/linux-mt6750-tablet**：同 SoC 家族（MT6755、MT6353 PMIC、MT6625L、k50v1 平板），33 个 `git format-patch` 补丁覆盖 dts/PMIC/充电/电量计/温控/pinctrl/eMMC/USB mtu3/Docker 配置。**md5 逐个核对官方仓库，逐字节一致**。
3. CONSYS WiFi 源码恢复为 pminervini 原版（6.12 污染全部还原）。

### 3.2 CI / 增量编译
- GitHub Actions，`workflow_dispatch`，120 min，2 vCPU / 7 GB
- 清华镜像拉 `linux-7.3.1.tar.gz`（缓存 `kernel-tarball-7.3.1`）
- `actions/cache@v4` 缓存 `build-tree.tar`（linux+out，~2.6G），key 含 `run_id` + 前缀 restore
- 补丁跳过用**标记文件** `linux/drivers/tty/serial/earlycon-ram.c`（`git am` 会剥掉 `[PATCH N/N]`，不能用 git log grep）
- 全量 ~14–16 min，增量 ~2.5 min

### 3.3 关键纠错（都是实测后改的）
| 我犯的错 | 纠正 |
|---|---|
| 以为 mainline 没有 BQ25890 驱动，要自己写 | **有**原生 `bq25890_charger.c`（`CONFIG_CHARGER_BQ25890`），只是我只看了 config 没查源码 |
| 用空骨架 dts（缺时钟/i2c/USB 节点） | 改成从 33 patch 打完后的**完整 k50v1 dts 派生** |
| 充电参数拍脑袋填 4.4V/1.5A | 按设备实测改成 **4.35V/1A**（stock 满充 4.37V，high_voltage_support=0） |
| sed 里 `&` 未转义导致 dts 语法错 | 用 `\&` |
| 把 stock ramdisk 当成可用 rootfs | 它是 Android/Flyme 的，不能用 |
| 以为设备缺 WiFi 固件 | 固件在 p29/p31，本来就有 |
| 以为 USB 是 musb | 是 MTU3 SSUSB |

## 4. 最终成果（编译/打包层面，均已验证）

### 4.1 内核
- Linux 7.3.1 + 33 官方 patch，CI 编译成功（最终 run `45790670725`）
- 产物 `kernel-mt6755-m5note-7.3.1` 15.2 MB；`Image.gz-dtb` 8.6 MB
- DTB 从产物读回确认：`meizu,m5note`、`mediatek,mt6755`、`ti,bq25890`、`mediatek,mt6755-i2c`
- reserved-memory 与 lk 保留区 **0 处重叠**

### 4.2 已编入的驱动（config 实测）
- 容器：`CGROUPS=y`、`NAMESPACES=y`、`NETFILTER/NF_CONNTRACK/NF_NAT/NF_TABLES=y`；模块 `BRIDGE/VETH/OVERLAY_FS/IP_VS/MACVLAN/IPVLAN/VXLAN/DUMMY`
- 存储/启动：`MMC_MTK/MMC_SDHCI/MMC_BLOCK/EXT4/VFAT/SQUASHFS=y`
- USB：`USB_MTU3=y`、`PHY_MTK_TPHY=y`
- 充电/电源：`CHARGER_BQ25890=y`（4.35V/1A）、`BATTERY_BQ27XXX`、`POWER_SUPPLY`、`THERMAL`、`CPU_THERMAL`
- 总线：`I2C_MT65XX=y`、`PINCTRL_MT6755=y`
- 串口/RAM console：`SERIAL_8250_MT6577`、`EARLYCON_RAM_FORCE`（HEAD@0xb00c0000，日志@0xb00d0000 64K，reserved-memory 覆盖无冲突）
- **明确没有**：GPU/DRM/LCD/touch（屏幕按约定放弃）

### 4.3 boot.img（已打包，未刷）
- 文件：`release/boot-mainline-m5note.img`
- 大小：**9,990,144 字节 = 9.53 MB**（boot 分区 16.8 MB）
- SHA256：`ba4405c05904f52bda7324dcb3ce0d7ff4052068d44fc6ff04de9dd701f6e5c6`
- 构成：原厂头(2KB，保留 MTK 私有字段) + `Image.gz+DTB`(8.96MB) + ramdisk(1.02MB)
- ramdisk = 静态 busybox 1.37.0(aarch64) + `init-direct`（mount p31 → `switch_root /data/debian /sbin/init`）
- 校验全过：magic、tags_addr、DTB magic/内容、cpio newc、SHA1 一致

## 5. 未验证 / 已知缺口（诚实清单）

| 项 | 状态 |
|---|---|
| **刷机运行** | **从未刷过**，所有"能跑"都是静态推断 |
| WiFi 运行 | `CONFIG_CFG80211=m`，4 个 .ko（cfg80211/wlan_gen2/mtk_wmt_wifi_soc/mtk_stp_wmt_soc）**未装进设备 `/lib/modules`（空）**→ 现状刷上去 WiFi 确定起不来 |
| USB 网络 / systemd | 未配 USB gadget；systemd 在 mainline 上能否起来未知 |
| 调试信息获取 | 内核早期靠 ramcon(0xb00d0000)+HEAD marker(0xb00c0000)，需 mtkclient DA 模式读物理内存；Stock 下 SSH/ADB 都走 WiFi，mainline 下 WiFi 未起则无网络 |
| 屏幕 | 放弃。唯一可行路线是 simple-framebuffer，但 lk 的 fb 物理地址未知；GPU/LCD 难度高 |
| BQ25890 实际充电 | 参数按 stock 保守设置，未上机验证 |

**结论：编译/打包层面完成；运行层面零验证。不能保证刷了能起来。**

## 6. 刷机前必做（如果决定刷）

1. 备份原 boot：`dd if=/dev/block/mmcblk0p22 of=/sdcard/boot.img.bak`
2. SP Flash Tool 核对：9.53 MB 的 img 填 **boot** 行，别填 lk 行（会溢出，只能 BROM 恢复）
3. 首次走 recovery/临时启动，不设默认启动
4. 先想好失败后怎么拿日志（见第 5 节 ramcon）

## 8. 经验教训（写给后来者）

1. **不要手工 backport 不匹配的内核 API**（6.12 的 cfg80211 签名地狱）——找版本匹配的现成项目。
2. **"编过了"≠"能用"**：模块（=m）必须装进 rootfs 才能加载；内建（=y）才在内核里。我一开始把两者混为一谈。
3. **来源要逐字节/md5 核对**，不要靠记忆和嘴说。
4. **参数要实测**：充电电压/电流、内存大小、i2c 地址都从设备读，不拍脑袋。
5. **先确认调试通道再谈刷机**：没有串口、网络又依赖未起的驱动时，failed boot = 哑巴，必须用带外手段（ramcon/DA peek）。
6. **chroot 视图会骗人**：从 chroot 内看不到宿主的真实 rootfs 位置；要用 ADB/另一条路径交叉验证。
7. **不要 premature 地把半成品包装成完成品**，也不要在没验证时推演"必然失败"——两者都是失真。
